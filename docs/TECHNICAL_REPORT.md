# التقرير التقني — منصة التحكم بكاميرات PTZ

> الإصدار 1.0 · Visual Basic / .NET 8 · الكاميرات: Hikvision DS-2SE7C432MW-AEB و DS-2DE7232IW-AE

## 1. ملخص تنفيذي

المنصة برنامج تحكم أمني بنافذتين مستقلتين (واحدة لكل كاميرا)، تجمع: تحكم PTZ كامل، ضبط الصورة والإضاءة والعدسة،
تحليل فيديو ذكي (كشف حركة، تتبع أجسام، تحليل سلوك، تتبع آلي، تسجيل مسارات)، ومنظومة أمان (تشفير الاتصال،
صلاحيات متعددة المستويات، سجل تدقيق مقاوم للعبث). الشيفرة مقسّمة بحيث يمكن اختبار كل المنطق دون واجهة رسومية.

**حالة التحقق (بصدق):**

| البند | الحالة |
|---|---|
| النواة والمقدِّمات | مبنية، 169 اختبار وحدة/تكامل ناجحة (Linux، .NET 8) |
| التشغيل عن بُعد (بوابة + عملاء) | مبني، 133 اختبار تكامل ناجح (خادم حقيقي، عميل إنتاجي، TLS حقيقي) + اختبار دخان بمتصفح حقيقي — انظر [REMOTE.md](REMOTE.md) |
| تكامل مع كاميرا ISAPI | **مع كاميرا وهمية** (`FakeCameraHandler`) تتحقق من الطلبات المرسلة والردود |
| واجهة WinForms | **تُجمَّع بنجاح** على Linux عبر حزمة المراجع؛ **لم تُشغَّل بصرياً** (لا Windows في بيئة التطوير) |
| كاميرات فعلية | **لم تُجرَّب** — مسارات ISAPI بحاجة اختبار قبول ميداني (انظر §3.3) |

│   كل نافذة = X.Designer.vb (تصميم) + X.vb (ربط أحداث فقط)                           │
│ لوحات UserControl وحيدة الوظيفة: PtzPanel ImagePanel SmartPanel AlarmPanel VideoView │
└───────────────▲──────────────────────────────────────────────────────────────────────┘

┌───────────────┴──────── Ptz.Presentation (net8.0، بلا WinForms) ────────────────────┐

│ CameraConfigStore (تخزين الإعدادات)  GeometryStore (المناطق والخطوط)                  │
└───────────────▲──────────────────────────────────────────────────────────────────────┘

│ Models │ Isapi (IsapiClient, IsapiXml, AlertStream, CertificateProbe)                │

│ Security (RBAC, UserStore, FileAuditLog, CredentialVault, SecuredCameraController)   │
└──────────────────────────────────────────────────────────────────────────────────────┘

**قرارات التصميم**

- **MVP بدل MVVM**: WinForms لا يملك ربط بيانات غنياً؛ MVP مع واجهات عرض يجعل كل المنطق قابلاً للاختبار بعروض مزيّفة
  (`FakeViews.vb`). نمط MVC لا يناسب WinForms لأن الأحداث تُوجَّه للعرض أولاً.
- **فصل صارم**: ملفات `*.Designer.vb` للتصميم فقط؛ ملفات الكود الخلفي تربط الأحداث وتُحوّل لأحداث عقد العرض بلا قرارات.
- **نافذة مستقلة لكل كاميرا**: `FrmDs2Se7c432mw` و`FrmDs2De7232iw` ومقدِّم لكل منهما؛ لا حالة مشتركة بينهما سوى الخدمات
  المحقونة (ناقل الإنذارات، التدقيق). كل وظيفة (PTZ/صورة/ذكاء/إنذارات/فيديو) في لوحة مستقلة — لا فورم يجمع وظائف.
- **أنماط**: Decorator (`SecuredCameraController`)، Factory (`CameraControllerFactory`)، Template Method (`CameraSessionPresenter`)،
  Observer (`AlarmBus`)، Table-driven (`ImageParamCatalog` — إضافة معامل صورة = صف جديد).
- **تعدد الخيوط**: التحليل على خيط خلفي واحد لكل كاميرا؛ أوامر PTZ تُسلسَل بـ `SemaphoreSlim`؛ حالة المحرك تحت قفل؛
  تحديثات الواجهة عبر `IUiDispatcher`؛ دمج أوامر الحركة المتلاحقة (coalescing) كي لا تتراكم الطلبات.

## 3. التحكم الكامل بالكاميرات

### 3.1 الخصائص

| المجال | الميزات |
|---|---|
| الحركة | حركة مستمرة متزامنة (Pan+Tilt+Zoom في أمر واحد)، سرعة 1–100، موضع مطلق (سمت/ارتفاع/تكبير)، تكبير على منطقة (Position3D)، رئيسية |
| المواضع | مواضع مسبقة (قراءة/حفظ/انتقال/حذف حتى 300)، دوريات (8)، أنماط (4: تسجيل/تشغيل/إيقاف) |
| العدسة | تركيز يدوي قريب/بعيد، نمط التركيز (Auto/Manual/SemiAuto)، فتحة |
| الصورة | سطوع، تباين، تشبّع، حدّة، تقليل ضجيج، نمط التعريض، فلتر IR (نهار/ليل/تلقائي)، WDR ومستواه، BLC، توازن الأبيض، إزالة الضباب |
| الإضاءة/الملحقات | الإضاءة المساعدة (IR) وسطوعها، الممسحة، إعادة التشغيل |
| الفيديو | لقطات JPEG عبر ISAPI (بديل البث) للعرض والتحليل؛ أحداث الكاميرا الذكية عبر `alertStream` |

### 3.2 آليات الموثوقية

- **مؤقّت أمان للحركة**: الحركة تُرسل عبر `momentary` بمدة 1000ms تُجدَّد أثناء الضغط؛ إن انقطع التطبيق تتوقف الكاميرا وحدها.
  إن لم يدعمها الطراز (404/501) يُرجع تلقائياً إلى `continuous`.
- **فحص القدرات الفعلية** (`CapabilityProbe`) عند الاتصال: الملف التعريفي افتراضي فقط؛ ما لا يستجيب يُعطَّل في الواجهة.
- **قراءة-تعديل-كتابة** لإعدادات الصورة: لا نمسح حقولاً لا نعرفها.
- إعادة محاولة لطلبات GET فقط (مرتان مع تراجع أسّي)، مهلة لكل طلب، سقف 8MB للاستجابة.
- المحرك الذكي: عند فشل الجلب يتراجع أسّياً (حتى 30 ث) ويُصدر إنذاراً حرجاً بعد 5 إخفاقات، ويوقف الكاميرا عند الإغلاق إن كانت تتحرك.

### 3.3 مسارات ISAPI المستخدمة ودرجة التأكد (مهم للاختبار الميداني)

كل المسارات مجمّعة في `IsapiPaths` ليسهل تعديلها حسب الإصدار البرمجي الثابت.

| المسار | الاستخدام | الثقة |
|---|---|---|
| `GET /ISAPI/System/deviceInfo` | معلومات الجهاز | عالية |
| `PUT /ISAPI/PTZCtrl/channels/1/continuous` | حركة/إيقاف | عالية |
| `PUT .../absolute` · `GET .../status` | موضع مطلق/قراءة | عالية (وحدات العشر درجات) |
| `GET/PUT/DELETE .../presets[/id[/goto]]` | المواضع المسبقة | عالية |
| `GET/PUT /ISAPI/Image/channels/1/{color,exposure,irCutFilter,WDR,BLC,whiteBalance,...}` | الصورة | متوسطة–عالية (أسماء العناصر تختلف بين الإصدارات؛ العنصر المفقود يعطي خطأ واضحاً) |
| `GET /ISAPI/Streaming/channels/101/picture` | لقطة | عالية |
| `GET /ISAPI/Event/notification/alertStream` | أحداث الكاميرا | عالية |
| `PUT .../momentary` | مؤقّت الأمان | متوسطة (يسقط تلقائياً لـ continuous) |
| `PUT .../position3D` | تكبير على منطقة | متوسطة |
| `PUT .../patrols/{id}/{start,stop}` · `.../patterns/{id}/{recordStart,recordStop,run,stop}` | دوريات/أنماط | **منخفضة–متوسطة**: أسماء الإجراءات تحتاج مطابقة مع وثيقة ISAPI للإصدار |
| `PUT .../homeposition[/goto]` | الرئيسية | متوسطة |
| `PUT .../auxcontrols/{id}` (Wiper=1, Light=2) | الممسحة/الإضاءة | **منخفضة**: معرّفات الأجهزة تختلف؛ قابلة للتجاوز في `AuxId()` |
| `PUT /ISAPI/System/Video/inputs/channels/1/{focus,iris}` | العدسة | متوسطة |
| `.../Image/channels/1/{defog,noiseReduce,supplementLight,focusConfiguration}` | ميزات إضافية | متوسطة (تُعطَّل تلقائياً إن لم تُدعم) |

**الخطوة الموصى بها**: تشغيل الاختبار الميداني (§9) على كل كاميرا، وتصحيح أي مسار يفشل في `IsapiPaths`/`ImageParamCatalog`
(سطر واحد لكل تصحيح) مع اختبار وحدة يثبّت الإصلاح.

## 4. الذكاء الاصطناعي في الفيديو

مسار المعالجة (`SmartEngine.ProcessFrame`) — دالة نقية بلا I/O وقابلة للاختبار:

```
لقطة JPEG → تدرج رمادي → تصغير (160 بكسل عرض) ─┬→ [كاميرا ثابتة] كشف الحركة → تتبع → سلوك → إنذارات
                                                 └→ [تتبع آلي نشط] متتبّع القالب → أوامر PTZ
```

| الوحدة | الطريقة |
|---|---|
| `BackgroundSubtractor` | نموذج غاوسي متكيّف لكل بكسل (متوسط+تباين متحرك)، تعلّم انتقائي (الأمامية أبطأ فتُمتصّ الأجسام الساكنة)، **حارس تغيّر الإضاءة** (>50% أمامية ⇒ إعادة تعلّم بلا إنذار) |
| `MotionDetector` | فتح مورفولوجي 3×3 ← كتل متصلة (8-اتصال) ← دمج المتجاورة ← ترشيح بالمساحة ← **مناطق إخفاء** (خصوصية/أشجار)؛ يُعلَّق أثناء حركة الكاميرا (`SuspendUntil`) |
| `ObjectTracker` | تتبع متعدد الأجسام: تنبؤ بسرعة ثابتة، مطابقة جشعة بالمسافة مع بوابة، مرشّح α-β، تأكيد بعد 3 إصابات، إنهاء بعد 1.5 ث |
| `TemplateTracker` | مطابقة قالب (SAD مع خروج مبكر) لملاحقة الهدف **أثناء حركة الكاميرا نفسها** حيث يفشل فصل الخلفية؛ يرفض الأهداف عديمة التفاصيل |
| `AutoTracker` | قفل الهدف (تلقائي: الأكبر×الأقدم، أو يدوي بنقر أيمن)، خطأ الموضع ← سرعة PTZ متناسبة مع منطقة ميتة وتنعيم أسّي، **تحكم التكبير** للحفاظ على حجم الهدف، مهلة فقدان |
| `BehaviorAnalyzer` | قواعد معرفية: **اقتحام منطقة**، **عبور خط** (باتجاه)، **تسكّع**، **سكون مطوّل**، **ركض**، **حركة متخبطة** (انعكاسات اتجاه >120°)، **تجمّع** |
| `SpeedAnomalyModel` | **تعلّم آلي خفيف**: توزيع السرعة الطبيعية لكل خلية من شبكة المشهد (Welford)، إنذار بـ z-score>3.5 بعد عيّنات كافية؛ يُحفظ ويُستعاد |
| `TrajectoryRecorder` / `HeatMap` | مسارات منتهية بصيغة JSONL يومية (نقاط مخفّضة) + خريطة حرارية للكثافة |

**حدود معروفة**
- تحليل السلوك يعمل والكاميرا **ثابتة**؛ أثناء حركتها لا تُعتبر مواضع الصورة مرجعاً (الحل المستقبلي: إسقاط على إحداثيات PTZ المطلقة).
- السرعات بوحدة «إطار/ثانية» تتغير مع التكبير؛ العتبات تُضبط لكل مشهد من لوحة الذكاء.
- المحرك لا يصنّف نوع الجسم (إنسان/مركبة). التكامل مع نموذج كشف (ONNX) نقطة توسّع: `IFrameSource` → كاشف بديل يُنتج `Detection`.
- الجودة محكومة بمعدل اللقطات (4–5 إطار/ث) لأن الفيديو عبر لقطات ISAPI؛ للمعدلات الأعلى يُضاف `IFrameSource` عبر SDK الشركة المصنّعة.

## 5. الأمان

| التهديد | الضابط |
|---|---|
| التنصت/الوسيط | HTTPS فقط افتراضياً (HTTP يتطلب تفعيلاً صريحاً)، TLS 1.2+، **تثبيت بصمة الشهادة** (SHA-256) مع أداة قراءتها وتأكيد المسؤول، بلا قبول لشهادات غير موثوقة |
| سرقة بيانات الاعتماد | كلمات مرور الكاميرات **AES-256-GCM** مرتبطة بسياقها، مفتاح رئيسي محميّ بـ **DPAPI**، لا تظهر في سجلات/`ToString`/استثناءات؛ لا إعادة توجيه HTTP؛ Basic فقط داخل TLS |
| الوصول غير المصرّح | **4 أدوار** (مشاهد/مشغّل/مشرف/مدير) و13 صلاحية دقيقة تُفرض في **طبقة واحدة** (`SecuredCameraController`) فلا يتجاوزها كود واجهة؛ انتهاء جلسة بالخمول (الاستطلاع الخلفي لا يجدّدها) |
| تخمين كلمات المرور | PBKDF2-SHA256 (210,000 دورة) بملح فريد، سياسة قوة، قفل 15 د بعد 5 محاولات، رسالة فشل موحّدة ومقارنة بزمن ثابت وحساب وهمي للمستخدم غير الموجود، **بلا كلمات مرور افتراضية** |
| إنكار/إخفاء الأفعال | **سجل تدقيق** JSONL مسلسل بـ HMAC-SHA256 (سلسلة تجزئة): يكشف التعديل والحذف من الوسط؛ كل عملية (OK/DENIED/FAIL) تُسجَّل؛ إدخالات مرتبة ومحصّنة ضد حقن الأسطر |
| حقن XML/مسارات | بناء XML عبر `XElement` (هروب تلقائي)، منع DTD/كيانات خارجية عند التحليل، التحقق من مسارات ISAPI (`/ISAPI/` فقط، بلا `..` أو `//`)، التحقق من النطاقات والقيم المسموحة، تنظيف أسماء المواضع |
| بث خبيث/ضخم | سقف 8MB للاستجابة و1MB لمخزن الأحداث، تجاهل XML التالف |
| الإنذارات الخارجية | Webhook **HTTPS فقط** بتوقيع HMAC + طابع زمني (ضد إعادة التشغيل)، طابور محدود لا يحجب التحليل |
| فشل آمن | مؤقّت أمان للحركة في الكاميرا؛ إيقاف الكاميرا عند إغلاق المحرك؛ أخطاء المشتركين معزولة |

**حدود الضمان**: سلسلة التدقيق تكشف العبث لكنها لا تمنع من يملك مفتاح HMAC من إعادة كتابتها كاملة، ولا تكشف بتر **نهاية** السجل
إلا إن حُفظت `LastHash` خارج الجهاز (يوصى بإرسالها دورياً إلى SIEM). DPAPI يحمي من المستخدمين الآخرين لا من برمجية خبيثة تعمل بحساب المستخدم نفسه.

### 5.1 التشغيل عن بُعد
أُضيفت بوابة (`Ptz.Gateway`) تفصل بيانات اعتماد الكاميرات عن المشغّلين البعيدين وتفرض عليهم: HTTPS مع تثبيت الشهادة، TOTP، رموز جلسة معتمة مُجزّأة، سقف دور للجلسات البعيدة،
تحققاً معزَّزاً للإجراءات الحساسة، عقد حركة PTZ يوقف الكاميرا عند اختفاء العميل، حصصاً ومعدلات، وتدقيقاً بهوية المستخدم الحقيقية، مع فحص إقلاع يرفض الإعدادات الخطرة.
النموذج الكامل والتهديدات والحدود في [REMOTE.md](REMOTE.md) §3 و§9. **لا يُستعمل Hik-Connect** لأنه بلا API عام للتحكم (§1 هناك).

## 6. واجهة المستخدم

- ثيم داكن موحّد (`Theme`) وعناصر مخصصة: `JoystickControl` (فأرة ولوحة مفاتيح)، `VideoView` (تراكبات: صناديق، مسارات، مناطق، خطوط، حالة)، `ThemedTabControl`.
- تفاعل الفيديو: سحب = تكبير على منطقة، نقر = توسيط، نقر أيمن = قفل هدف للتتبع، رسم مناطق/خطوط بالنقر (نقرة مزدوجة للإنهاء، Esc للإلغاء).
- تعطيل العناصر بحسب الصلاحية (للوضوح فقط؛ الفرض الفعلي في الطبقة الأمنية).
- النصوص العربية مركزة في `UiText`؛ التخطيط LTR مع نصوص عربية (التحويل لـ RTL كامل ممكن لاحقاً لكنه يتطلب اختباراً بصرياً).

## 8. خطة الصيانة والتوسع

- **إضافة معامل صورة**: صف في `ImageParamCatalog` + عنصر في اللوحة والخريطة في `ImagePanel` (يظهر تلقائياً في القراءة/التطبيق/التدقيق).
- **تصحيح مسار ISAPI لإصدار برمجي**: تعديل `IsapiPaths` أو تجاوز `AuxId/AuxType` في الصنف الوريث + اختبار.
- **إضافة طراز كاميرا**: `CameraProfile` جديد + صنف وريث من `HikvisionPtzController` + مقدِّم ونافذة (نسخ نافذة موجودة) + سطر في `CameraControllerFactory`.
- **بث فيديو عالي المعدل**: تنفيذ `IFrameSource` عبر SDK الشركة المصنّعة (HCNetSDK) أو RTSP، دون لمس المحرك.
- **كشف أجسام بشبكة عصبية**: كاشف يُنتج `Detection` يحلّ محل `MotionDetector` في `SmartEngine`.
- **تكامل الإنذارات**: مستقبِل جديد `IAlarmSink` (Syslog/MQTT/SIEM)؛ Webhook جاهز.
- **ترحيل**: ملفات JSON مُنسخة؛ أضف حقل `Version` عند تغيير البنية. قوالب CI في `.github/workflows/ci.yml` (Linux: بناء+اختبار+فحص تجميع الواجهة؛ Windows: بناء التطبيق).
- **مراجعات دورية**: تدوير مفتاح HMAC/الخزنة، حفظ `LastHash` خارجياً، مراجعة التبعيات (الاعتماد الوحيد خارج .NET هو `System.Security.Cryptography.ProtectedData` من Microsoft، وxUnit للاختبار فقط).

## 9. اختبار القبول الميداني المطلوب قبل الإنتاج

1. الاتصال بكل كاميرا وقراءة البصمة وتثبيتها؛ مقارنتها بالبصمة في واجهة الكاميرا.
2. التحقق من `CapabilityProbe`: أي ميزة تظهر معطّلة خطأً تدل على مسار/عنصر مختلف في إصدارك.
3. PTZ: حركة/إيقاف/مؤقّت الأمان (اقتل التطبيق أثناء الحركة ← يجب أن تتوقف خلال ~1 ث)، موضع مطلق، تكبير على منطقة.
4. مواضع مسبقة/دوريات/أنماط/رئيسية/ممسحة/إضاءة (الأكثر احتمالاً للاختلاف).
5. ضبط عتبات الكشف في مشهدك الحقيقي (الإضاءة، الأشجار ← مناطق إخفاء)، وفترة تعلّم نموذج الشذوذ (افتراضياً 10 دقائق).
6. اختبار تحميل: تشغيل النافذتين لساعات، مراقبة الذاكرة والمعالج والشبكة.
7. مراجعة أمنية مستقلة (اختبار اختراق) قبل نشر الجهاز في شبكة حساسة.
