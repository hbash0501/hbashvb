# التشغيل عن بُعد — البوابة (Gateway) والعملاء

> الهدف: تشغيل الكاميرتين (DS-2SE7C432MW-AEB وDS-2DE7232IW-AE) من خارج شبكتهما بأمان، مع الإبقاء على كل ضوابط
> المنصة: صلاحيات متعددة المستويات، سجل تدقيق مقاوم للعبث، وتحليل ذكي يعمل على مدار الساعة.

## 1. لماذا لا Hik-Connect؟ (وما الذي اخترناه)

طُلب التشغيل «عبر Hik-Connect أو أي بروتوكول». بعد بحث الخيارات، **Hik-Connect وحده لا يصلح كناقل برمجي** لهذه المنصة:

| الخيار | الحكم |
|---|---|
| **Hik-Connect (تطبيق/سحابة Hikvision)** | لا يوجد API عام يسمح لتطبيق طرف ثالث بتحريك PTZ أو سحب الفيديو عبر السحابة؛ هو تطبيق مغلق للمشاهدة اليدوية. يصلح كمشاهد **منفصل** يعمل بجانب المنصة، لكن لا يمكن دمجه ولا يمرّ عبر صلاحياتنا وتدقيقنا. |
| **ISUP (EHome)** | بروتوكول تسجيل الأجهزة على خادم يستقبل اتصالات الكاميرات؛ يتطلب SDK مغلقاً وترخيص شريك من Hikvision ويعني فتح خادم عام يستقبل الأجهزة. خارج «المكتبات المعتمدة» ومخاطرته أعلى. |
| فتح منفذ الكاميرا على الإنترنت (Port-forward/DDNS) | **مرفوض**: يعرّض واجهة الكاميرا المعروفة بثغراتها مباشرة للإنترنت. |
| VPN إلى شبكة الكاميرات + التطبيق الحالي مباشرة | يعمل، لكن بلا تحليل على مدار الساعة (يتوقف عند إغلاق التطبيق) ولا فصل بين بيانات اعتماد الكاميرا والمشغّل البعيد (كل مشغّل يحتاج كلمة مرور الكاميرا). |
| **بوابة داخل الشبكة (المختار)** | تملك وحدها بيانات اعتماد الكاميرات، تشغّل المحرك الذكي 24/7، وتعرض واجهة REST/SSE محمية للعملاء. هي النقطة الوحيدة المعرَّضة (خلف VPN/نفق)، والكاميرات تبقى غير مرئية من الخارج. |

النتيجة: **البوابة** + عميلان: تطبيق WinForms بـ«وضع البوابة»، وكونسول ويب للجوال/المتصفح. الاثنان يمرّان بالقواعد نفسها.

## 2. البنية

```
 كاميرا SE ─┐                                     ┌─ تطبيق WinForms (وضع البوابة)
            ├─ ISAPI/HTTPS+Digest ─► البوابة ◄─HTTPS (REST + SSE)─┤
 كاميرا DE ─┘   (LAN فقط)        PtzGateway        └─ كونسول ويب (جوال/متصفح)
                                  │  ├─ المحرك الذكي 24/7 (حركة، تتبع، سلوك، تتبع آلي)
                                  │  ├─ الصلاحيات والجلسات وTOTP
                                  │  └─ سجل التدقيق (سلسلة HMAC) + الإنذارات
                          VPN / WireGuard / Tailscale / Cloudflare Tunnel (الطبقة الخارجية)
```

- **مشروع `src/Ptz.Gateway`** (Kestrel/ASP.NET Core، `PtzGateway`): الخادم + أداة الإدارة (CLI) + الكونسول المضمَّن.
- **عميل** في `Ptz.Core/Remote/Client` (`GatewayClient`, `RemoteCameraController`, `RemoteSmartEngine`, `GatewayEventStream`,
  `RemoteJpegFeed`...) يُركَّب عبر `ICameraBackendFactory` فتعمل **المقدِّمات والنوافذ نفسها** (لا تعرف الفرق بين الوضعين).
- الدمج المحلي/البعيد: `LocalCameraBackendFactory` (اتصال مباشر كما كان) أو `GatewayBackendFactory` (عبر البوابة).

## 3. نموذج الأمان

| التهديد | الضابط |
|---|---|
| تعريض الكاميرات | لا تُعرَّض. بياناتها (AES-256-GCM) على البوابة فقط؛ لا تصل لأي عميل. العملاء لا يرون عناوين الكاميرات ولا أرقامها التسلسلية (ما لم يملكوا صلاحية الصيانة) |
| التنصت/الوسيط | **HTTPS إلزامي** (يرفض الخادم غير الحلقة المحلية بلا HTTPS)؛ العميل يثبّت الشهادة (`spki-sha256`/`cert-sha256`، حتى بصمتين) ولا يوجد «قبول الكل»؛ فشل التحقق يمنع إرسال أي كلمة مرور (مُختبر بمصافحة TLS حقيقية) |
| سرقة/تخمين الدخول | كلمة مرور + **TOTP (RFC 6238)** إلزامي افتراضياً مع حارس إعادة الاستعمال؛ رسالة فشل موحّدة (متطابقة بايتاً)؛ تحديد معدل من بيانات المسار؛ قفل مؤقت للمستخدم بعد إخفاقات TOTP فقط (لا يُستعمل للحرمان من الخدمة بأسماء مزيّفة) |
| سرقة الرمز | رمز عشوائي معتم (`ptzs_` + 256 بت)، يُخزَّن **تجزئته** فقط في ذاكرة الخادم، يُرسل في `Authorization` فقط (يُرفض في الاستعلام)، وفي الكونسول يعيش في متغير ذاكرة لا في أي تخزين |
| تصعيد الصلاحيات | سقف دور للجلسات البعيدة (`remoteMaxRole`، الافتراضي مشرف؛ المدير البعيد يتطلب متغير بيئة صريحاً)؛ الصلاحيات تُفرض **على الخادم** (واجهة العميل للوضوح فقط)؛ بصمة أمان تُفحص كل طلب فتسقط الجلسات عند تغيير كلمة المرور/الدور/TOTP/التعطيل |
| إجراءات حساسة | **تحقق معزَّز (Step-up)**: تغيير عتبات/هندسة الذكاء وتعطيل الكشف يتطلبان رمز TOTP جديداً خلال 5 دقائق |
| كاميرا تبقى تدور | **عقد حركة**: كل أمر حركة يحمل مهلة (ttl) ورقماً تسلسلياً ويُجدَّد دورياً؛ إن اختفى العميل (انهيار/نفق ميت/إبطال جلسة) توقف البوابة الكاميرا وحدها؛ التجديد من مشغّل لا يتغلب على إيقاف مشغّل آخر |
| العدسة (تركيز/حدقة) | لا عقد لها بطبيعتها، فللبوابة **مراقب 3 ث**: أي أمر حركة عدسة بلا halt لاحق (شبكة، 429، انهيار) توقفه البوابة بنفسها، وتوقفه فوراً عند إبطال الجلسة أو إيقاف الخدمة |
| الحرمان من الخدمة | حصص بثوث لكل مستخدم/عامة، حدود حجم الطلب والاستجابة، مهل لكل مسار، طوابير محدودة لا تحجب المحرك (العميل البطيء يُفصل)، لقطة واحدة في الرحلة؛ **قراءات الكاميرا الثقيلة** (صورة/موضع/مواضع) بتحديد معدل لكل جلسة وبوابة تزامن (2) لكل كاميرا كي لا يُغرق مشاهد واحد خادم الكاميرا؛ فتح/إغلاق البثوث محدود المعدل |
| فيض سجل التدقيق | تجميع التجاوزات يتطابق مع مفتاح تحديد المعدل (IPv6 على /64)، سقف عام 60 سطراً/دقيقة مع ملخص للفائض (حتى بعد انتهاء الهجوم)، وإيقاف الحركة يُدقَّق بسطر/ث؛ القراءة من ذيل الملف (لا تحمّل السجل كله) والتحقق متدفق بلا حدّ 2GB، والأسطر المبتورة (قطع كهرباء) لا توقف الإقلاع ولا تُبطل السلسلة (العبث الحقيقي يُكشف دائماً) |
| إنكار الأفعال | كل عملية مغيِّرة تُدقَّق باسم المستخدم الحقيقي وعنوانه ومعرّف الجلسة (سلسلة HMAC)؛ **تتوقف العمليات المغيِّرة إن تعذّر التدقيق** (عدا الإيقاف/الخروج)؛ أداة الإدارة تكتب سلسلة مستقلة `audit-admin.log` |
| حقن/XSS | JSON صارم (يرفض الحقول المجهولة)، تحقق من كل حقل قبل بلوغ الكاميرا، الكونسول بـ CSP صارم (`script-src 'self'` بلا inline) ولا `innerHTML` ولا `eval` (مُختبر آلياً) |
| سوء الإعداد | **فحص إقلاع** يرفض الإقلاع عند: استماع خارجي بلا TLS صالح، `allowedHosts` فارغ/`*`، وكلاء موثوقين غير صالحين، **وضع Tunnel بلا `trustedProxies`** (وإلا اشترك كل العملاء في مفتاح معدل واحد فيحجب مجهول واحد دخول الجميع)، TOTP معطّل خارج Loopback/Vpn، مدير بعيد بلا موافقة، لا مستخدمين، كاميرا HTTP بلا موافقة، ملف المفتاح بصلاحيات واسعة |

### ما لا تحميه البوابة (واضح وصريح)
- **من يملك مضيف البوابة يملك كل شيء** (المفتاح الرئيسي والبيانات على القرص نفسه). احمِ المضيف كخادم أمني.
- سلسلة التدقيق تكشف العبث لكنها لا تمنع من يملك المفتاح من إعادة كتابتها؛ استعمل `auditAnchorFile` على وسط منفصل.
- الجلسات في الذاكرة: إعادة تشغيل البوابة تُخرج الجميع (مقصود وآمن).
- لا mTLS؛ الاعتماد على VPN/نفق + كلمة مرور + TOTP.

## 4. المتطلبات والبناء

- مضيف للبوابة داخل شبكة الكاميرات: Linux (موصى به) أو Windows، .NET 8 Runtime (ASP.NET Core).
- **تبعيات خارج .NET للبوابة (وللبوابة فقط)**: `SkiaSharp` (MIT) لفك ترميز/إعادة ترميز JPEG بتوافق متعدد المنصات (التطبيق المكتبي يبقى على
  `System.Drawing` كما كان). اختُبرت الإصدارات المثبَّتة في `Ptz.Gateway.vbproj`؛ إن لزم استبدالها فالحدود هي `IFrameDecoder`/`IJpegTranscoder`.
  اختبارات التكامل تستعمل `Microsoft.AspNetCore.TestHost` (اختبارات فقط).
- النشر:

```bash
dotnet publish src/Ptz.Gateway -c Release -o /opt/ptz-gateway
```

ملفات جاهزة في [`deploy/`](../deploy): `gateway.example.json`، `ptz-gateway.service` (systemd مقيَّد)، `nftables.example.conf`،
`Dockerfile` + `docker-compose.example.yml`، `install-windows-service.ps1` (لم تُختبر الحاوية ولا خدمة Windows في بيئة التطوير).

## 5. الإعداد والتشغيل

### 5.1 الأوامر الإدارية (محلية على مضيف البوابة فقط — لا API بعيد لها)

```bash
export PTZ_GATEWAY_CONFIG=/etc/ptz-gateway/gateway.json
export PTZ_MASTER_KEY_FILE=/etc/ptz-gateway/master.key     # يُنشأ عند أول تشغيل؛ احفظ نسخة احتياطية آمنة منه
GW=/opt/ptz-gateway/PtzGateway

$GW user add alice operator        # كلمة المرور من الطرفية (بلا صدى) أو من stdin عند الأتمتة؛ سياسة 12+ حرفاً
$GW totp enroll alice              # يطبع سر TOTP ورابط otpauth:// مرة واحدة فقط — أضفه إلى تطبيق المصادقة
$GW camera set se7c432mw --host 192.168.1.64 --user svc --name "Gate" --pin <sha256 اختياري>
$GW camera set de7232iw  --host 192.168.1.65 --user svc --name "Yard"
$GW cert create --host gateway.lan --days 365    # شهادة ذاتية التوقيع + طباعة بصمتي spki/cert للعملاء
$GW cert show                      # إعادة طباعة البصمات
$GW check                          # فحص الإعداد بلا تشغيل
$GW serve                          # التشغيل (الافتراضي)

$GW user list | role <name> <role> | disable|enable|unlock <name> | passwd <name>
$GW totp reset <name>              # إلغاء TOTP (تسقط الجلسات)
$GW revoke-all                     # إبطال كل الجلسات الحالية خلال ثوانٍ
$GW verify-audit                   # التحقق من سلاسل audit.log وaudit-admin.log (رمز خروج 3 عند العطب)
$GW rotate-audit                   # (والخدمة متوقفة) يتحقق ثم يؤرشف audit.log إلى audit-<UTC>.log فيبدأ سجل جديد
```

الأدوار: `viewer` (مشاهدة)، `operator` (+PTZ/مواضع/تتبع/إقرار)، `supervisor` (+صورة/إعدادات ذكاء/تدقيق)، `administrator`.

### 5.2 مرجع الإعداد (`gateway.json`، تعليقات `//` مسموحة)

| الحقل | الافتراضي | الوصف |
|---|---|---|
| `exposureMode` | `Loopback` | `Loopback` \| `Vpn` \| `Tunnel` \| `Public`؛ يحدد صرامة فحص الإقلاع فقط |
| `listen` | `127.0.0.1:8443` | عناوين الاستماع؛ اربط على واجهة الـ VPN لا `0.0.0.0` |
| `tls` | — | `pfxPath` (+`pfxPasswordEnv`) أو `pemPath`/`pemKeyPath`؛ **إلزامي** لأي استماع خارج الحلقة المحلية |
| `allowedHosts` | localhost... | أسماء `Host` المقبولة (لا `*` مع استماع خارجي) |
| `trustedProxies` | `[]` | عناوين الوكلاء/النفق الموثوقين مفردةً (يُقرأ منها `X-Forwarded-For/Proto`)؛ بلا نطاقات ولا `0.0.0.0` |
| `dataDir` | `/var/lib/ptz-gateway` أو `%ProgramData%\PtzGateway` | مجلد البيانات (صلاحيات المالك فقط) |
| `auditAnchorFile` | `""` | ملف يُلحق به آخر تجزئة تدقيق كل 15 د |
| `auth.*` | TOTP إلزامي، خمول 30 د، مطلق 12 س، 5 جلسات، step-up 5 د، `remoteMaxRole=Supervisor` | `allowNoMfa` لا يعمل إلا مع Loopback/Vpn |
| `streams.*` / `ptz.*` / `frames.*` | انظر `deploy/gateway.example.json` | حصص البثوث، مهلة عقد الحركة (200–2000 ms)، سلّم جودة الفيديو (`maxTier`) |
| `startEngines` | `true` | تشغيل المحرك الذكي لكل كاميرا عند الإقلاع |
| `webhook` | معطّل | إنذارات إلى نظام خارجي (HTTPS فقط، HMAC؛ السر من متغير بيئة) |

متغيرات البيئة: `PTZ_GATEWAY_CONFIG`، `PTZ_MASTER_KEY_FILE`، `PTZ_ALLOW_REMOTE_ADMIN=1` (للسماح بمدير بعيد فقط).

### 5.3 الشبكة الخارجية (اختر واحداً)

1. **VPN (WireGuard/OpenVPN) إلى مضيف البوابة** — الأبسط والأقوى: `exposureMode=Vpn` واستماع على عنوان الـ VPN (انظر `nftables.example.conf`).
2. **Tailscale/ZeroTier** — نفس الفكرة بلا فتح منافذ؛ اربط البوابة على واجهة الشبكة الخاصة.
3. **Cloudflare Tunnel/وكيل عكسي** — `exposureMode=Tunnel` + `trustedProxies` بعنوان الوكيل (وإلا تتشارك كل العملاء حصة معدل واحدة؛ يحذّرك الفاحص). أضف طبقة هوية (Access) أمام الوكيل إن أمكن. لا تُفعّل `Public` إلا مع مبرر وحماية إضافية.

لا تفتح منفذ البوابة على الإنترنت مباشرة، ولا منافذ الكاميرات أبداً.

## 6. العملاء

### 6.1 تطبيق WinForms (وضع البوابة)
1. شغّل التطبيق ← في شاشة الدخول اضغط **«اتصال ببوابة بعيدة…»**.
2. أدخل عنوان البوابة (`https://gateway.lan:8443`). اضغط **«قراءة الشهادة»** وقارن البصمة حرفاً بحرف بمخرجات `PtzGateway cert show` (`cert-sha256`) ثم أكّد — أو الصق `spki-sha256:…` مباشرة (تبقى صالحة عند تجديد الشهادة بالمفتاح نفسه).
3. أدخل المستخدم وكلمة المرور ورمز التحقق (6 أرقام). عند النجاح يظهر المحور بحالة كل كاميرا كما تعلنها البوابة، وتفتح نافذتا الكاميرتين المستقلتان كالمعتاد.
4. لا تُخزَّن على جهاز العميل كلمات مرور ولا رموز ولا إعدادات كاميرات؛ فقط آخر عنوان وبصمة.
5. الإجراءات الحساسة تفتح نافذة طلب رمز TOTP جديد. انتهاء الجلسة/إبطالها من الخادم يعيد لشاشة الدخول.

### 6.2 كونسول الويب (جوال/متصفح)
افتح `https://gateway.lan:8443/` (يمكن «إضافة إلى الشاشة الرئيسية»). واجهة عربية RTL: مشاهدة حية تتكيّف مع سرعة الشبكة، عصا تحكم باللمس
(Stop مضمون عند رفع الإصبع/إخفاء التبويب/فقدان الاتصال)، مواضع، صورة، ذكاء (مناطق/خطوط مع ETag)، إنذارات بتنبيه صوتي/إشعار، إدارة الجلسات والتدقيق.

### 6.3 الحاوية (اختياري)
`docker build -f deploy/Dockerfile -t ptz-gateway .` ثم `deploy/docker-compose.example.yml`. أنشئ `master.key` وملف الإعداد قبل التشغيل،
ونفّذ الأوامر الإدارية بـ `docker compose run --rm ptz-gateway user add ...`.

## 7. مرجع الواجهة (REST/SSE، الإصدار 1)

كل المسارات تحت `/api/v1`، JSON camelCase، الأخطاء `{ "error": { "code", "message", "requestId", ... } }`، رمز `Authorization: Bearer`.

| الجزء | المسارات (الصلاحية) |
|---|---|
| الدخول | `POST auth/login` (مجهول، تحديد معدل صارم) · `POST auth/stepup` · `POST auth/logout` · `GET auth/me` · `GET/DELETE auth/sessions[/{ref}]` · `GET server` · `GET /healthz` |
| الكاميرات | `GET cameras[/{cam}]` · `POST cameras/{cam}/connect` (مشاهدة) · `GET status` |
| الحركة | `POST …/ptz/move` `{pan,tilt,zoom,ttlMs?,seq?,renew?}` · `POST …/ptz/stop` (PtzControl) · `GET/PUT …/ptz/position` · `POST …/ptz/zoom-area` · `POST/PUT …/ptz/home` |
| المواضع | `GET/PUT/DELETE …/presets[/{n}]` · `POST …/presets/{n}/goto` · `POST …/patrols/{n}/start|stop` · `POST …/patterns/{n}/run|stop|record/start|record/stop` |
| العدسة والصورة | `POST …/lens/focus|iris` · `GET/PUT …/image` · `PUT …/aux/{wiper|light}` (ImageControl) |
| الفيديو | `GET …/snapshot[?fresh=1&tier=]` · `GET …/frame?tier=&after=&wait=` (استعلام طويل؛ طبقات `tiny|low|mid|high|hd`) |
| الذكاء | `GET/PUT …/smart/state` · `GET/PUT …/smart/behavior` (+step-up) · `GET/PUT …/smart/geometry` (ETag/`If-Match`، +step-up) · `POST/DELETE …/smart/target` · `POST …/smart/anomaly/save` |
| الأحداث | `GET …/events` (SSE: `hello`، `ov` تراكب، `alarm`، `state`، `geo`، `health`، `ack`، `resync`، `bye`؛ استئناف بـ `Last-Event-ID`) |
| الإنذارات والتدقيق | `GET alarms` · `POST alarms/{id}/ack` · `GET audit` · `GET audit/verify` (مشرف) |
| الصيانة | `POST …/device/reboot` يُسجَّل **فقط** إن سُمح بمدير بعيد صراحةً |

**عقد الحركة**: أرسل `move` عند الضغط ثم **جدّد** بـ `renew:true` كل ≈ ttl/3 برقم `seq` متزايد؛ ارفع الإصبع ⇒ `stop`. التأخر ⇒ `409 stale_seq` (يُتجاهل).

## 8. العمليات والصيانة

- **المراقبة**: `GET /healthz`؛ `GET /api/v1/status`؛ إنذار `System` (قاطع الكاميرا بعد رفضين لبيانات الاعتماد، تغيّر إعدادات الذكاء).
- **النسخ الاحتياطي**: مجلد البيانات + `master.key` (بدونه تضيع بيانات الكاميرات وأسرار TOTP المشفّرة). احتفظ بهما منفصلين ومشفّرين.
- **التحقق من السجل**: `PtzGateway verify-audit` دورياً (cron/systemd timer) + `auditAnchorFile` على وسط منفصل.
- **تدوير السجل**: لا تدوير تلقائي (السلسلة متصلة عمداً). راقب حجمه (تحدّد المعدلات نموّه لكنه يتراكم)، وكل شهر مثلاً: أوقف الخدمة ← `PtzGateway rotate-audit` (يرفض إن كانت السلسلة معطوبة) ← شغّلها.
  الأرشيف يُتحقَّق منه وحده بالمفتاح نفسه؛ يُسجَّل التدوير في `audit-admin.log` وفي ملف المرساة.
- **تدوير**: غيّر كلمات مرور حسابات الخدمة على الكاميرات بـ `camera set ... ` (تُطبَّق بعد إعادة تشغيل الخدمة)؛ `revoke-all` عند الاشتباه؛ جدّد الشهادة بـ `cert create` وحدّث البصمة (استعمل `spki-sha256` لتبقى صالحة).
- **حساب الخدمة على الكاميرا**: أنشئ مستخدماً مخصصاً بصلاحيات PTZ/صورة فقط (ليس admin) واستعمله في البوابة.

## 9. حدود معروفة ومؤجَّلات

- **لم تُجرَّب على كاميرات فعلية بعد** ولا على Windows بصرياً؛ الاختبار الآلي بكاميرا وهمية (`FakeCameraHandler`) وخادم كاميرا وهمي في اختبار دخان بمتصفح حقيقي (§10).
- FIPS/HSM لحفظ المفتاح الرئيسي، mTLS للعملاء، جلسات مستمرة عبر إعادة التشغيل، وعدّة نسخ من البوابة (HA): غير مدعومة.
- فيديو الجوال لقطات JPEG متكيفة (≈2–5 إطار/ث) لا RTSP/WebRTC؛ للحركة الأسلس أضف `IFrameSource` عبر SDK الشركة.
- .NET 8 ينتهي دعمه في نوفمبر 2026: خطّط للترقية إلى .NET 10 LTS (لا تغيير في البنية).
- إدارة المستخدمين وTOTP والكاميرات والشهادات **عبر CLI محلي فقط** عمداً (لا سطح هجوم بعيد لها).
- أوامر العدسة تُحدّد معدلها مع بقية الأوامر (5/ث)؛ الإيقاف قد يُرفض بـ 429 تحت ضغط شديد من الجلسة نفسها، وشبكة الأمان هي مراقب البوابة (3 ث) وإعادة محاولة العميل.
- لا يوجد Hik-Connect/ISUP كما فُصّل في §1.

## 11. اختبار القبول الميداني (إضافة إلى §9 من التقرير التقني)

1. من خارج الشبكة عبر VPN: دخول، رؤية الكاميرتين متصلتين، فيديو حي.
2. **أغلق التطبيق/افصل الشبكة أثناء حركة PTZ** ← يجب أن تتوقف الكاميرا خلال ثانيتين.
3. أرسل رمز TOTP خاطئاً مراراً ← قفل مؤقت؛ تحقق أنه لا يمنع بقية المستخدمين.
4. `revoke-all` أثناء بث ← ينتهي بث الأجهزة خلال ثوانٍ وترجع لشاشة الدخول.
5. غيّر شهادة البوابة ← يجب أن يرفض العميل (البصمة) ولا يرسل كلمة المرور.
6. راجع `audit.log` عبر واجهة التدقيق و`verify-audit`؛ جرّب تعديل سطر ← يُكتشف.
7. اختبار اختراق مستقل للبوابة قبل التعريض عبر نفق عام.
